# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ModelMeetsReality (MMR) is the **engine** for a fleet of forecasting models. A "model"
here is a document, not weights: premises, a mechanism, at least one falsifiable
consequence with a date, and a deletion clause. The engine scaffolds those documents,
runs them against live web sources to register dated claims, and grades those claims
when their dates arrive.

`README.md` is the user-facing tour and `SETUP.md` the install walkthrough — read those
for the product story. This file covers what is not obvious from them.

## Layout: one engine, many sibling repos

This directory (`MMR/`) is the **main instance** — all code, no model data. Each model
is its own independent git repo, a **sibling** of this one:

```
E:\New folder\          <- workspace, NOT a repo
  MMR\                  <- this repo: suites/ harness/ ui/ docs/ fleet.json
  ai-pressure\          <- a model repo (own .git)
  canon\                <- another
  ...44 more
```

`fleet.json` is the single registry every suite reads. `harness/fleet.py` resolves
model paths: `MODELS_DIR` env > `fleet.json`'s `models_dir` key > `ROOT.parent`. No
`models_dir` is set here, so **siblings of MMR is the live layout** — a `--repo foo`
flag means `../foo`. (Caveat: older suites such as `model_watch` hardcode their own
`parents[2]` rather than importing `MODELS_DIR`, so setting `models_dir` would not move
them.)

Never write model content inside MMR. Scaffold a sibling instead:

```bash
python -m suites.new_model my-model --title "My Model" --domain "what it models" --level 0
```

### What a model repo contains

In practice, the working siblings here carry: `MODEL.md` (premises / falsifiable
consequences / deletion clause — 43 of 46 have one), `watch.json` (the per-repo config
`model_watch` drives itself from: `frame`, `entities`, `ledger` path),
`predict/ledger.json` (your claims), `imported/ledger.json` + `IMPORTED.md` (claims
inherited from someone else's model — quarantined, never graded as your own), and
`index.jsonl` (memory index). Some add `USE.md` + `TASKS.md` (the paste-into-an-assistant
path) and `registry.json` / `verdicts.json`.

`docs/MODEL_SPEC_V1.md` additionally requires `model.json` (machine card, `record` holds
**counts only**) and `LICENSE` — but that is the contract for a repo that is going to be
**shared or listed**, generated by `make_card` / `publish_model`. No private sibling here
has a `model.json`. Don't go looking for 46 of them.

## Commands

All commands run **from the MMR root** as modules — `python -m suites.X`. Both the
module path and the `fleet.json` lookup depend on that cwd. Python 3.10+, stdlib only
for the core (see `requirements.txt` for the two optional extras).

```bash
# the loop
python -m suites.model_watch --repo <model> --predict   # observe (web) + register dated claims
python -m suites.model_watch --repo <model> --assess    # grade what's due
python -m suites.model_watch --repo <model> --status
python -m suites.grading_loop --dry                     # what's due fleet-wide, run nothing
python -m suites.grading_loop                           # full pass (schedule weekly)
python -m suites.trajectory                             # graded rows keyed by model VERSION
python -m suites.postmortem --run                       # earned vs LUCKY hits

# scaffolding
python -m suites.starter --list ; python -m suites.starter --new B1
python -m suites.new_model <slug> --title "..." --domain "..." --level 0

# cockpit
python ui/server.py                                     # http://127.0.0.1:8787, localhost only
                                                        # --port, else COCKPIT_PORT, else fleet.json cockpit_port

# arena (blind adversarial evaluation)
python -m suites.arena --case <case>
```

### Checks — there is no pytest

The two things that function as the test suite, both run before calling a change done:

```bash
python -m suites.compat_check          # does this still work at every installation level?
python -m suites.arena_test            # blindness invariants for the arena
bash scripts/preflight.sh              # before sharing: gated names, key shapes, .env tracked, CRLF
```

`compat_check` reports `MANUAL` for the pasted-prompt path and `skip` for anything not
installed here. **Neither is a pass** — `skip` means unverified, `MANUAL` means a human
must open an assistant session and paste. See `docs/COMPATIBILITY.md`.

## The compatibility doctrine

Every change must work at **three installation levels**, which share almost nothing:

1. **ASSISTANT** — someone pastes `USE.md` into ChatGPT/Claude/Gemini. No Python, no
   clone. Largest audience, easiest to break silently, because nothing executes to tell
   you. `USE.md` must keep its `QUOTED VERBATIM` fences (dropping them makes the paste-in
   path injectable) and must follow Review → Explain → Confirm → Apply.
2. **LOCAL** — the suites on the host. The offline spine (`import_model`,
   `legitimacy_audit`, `freeze_check`, `make_card`, `make_use`, `make_tasks`) must run
   with no model and no network; that property is what makes level 3 possible.
3. **DOCKER** — `docker/sandbox.Dockerfile` (no network, no credential, no model — for
   untrusted imports) and `docker/agent.Dockerfile` (network + one credential + one
   model). Driven by `scripts/sandbox_import.sh` and `scripts/sandbox_agent.sh`.

## The LLM layer

All suites call one function — `harness.openrouter.chat(model, messages, research=...)`.
Same signature across three backends, selected by `LLM_BACKEND`:

- **`openrouter`** (default) — plain urllib, no SDK. `OPENROUTER_BASE` accepts any
  OpenAI-compatible endpoint, so Ollama/LM Studio/vLLM work unchanged.
- **`claude-code`** — shells out to the `claude` CLI in print mode, billing an existing
  subscription instead of a key. Prompt goes via **stdin** (Windows argv caps ~32k).
  `research=True` appends a `:online` suffix, which switches the CLI to
  `--output-format stream-json --allowedTools WebSearch` so tool-result URLs are
  harvestable. Non-Anthropic slugs run as `sonnet`.
- **local** — has no web capability. A `research=True` call still runs and answers from
  the brief, returning `researched=False`. Degrading loudly beats crashing; degrading
  silently would file a brief-only read as researched.

Three model-name namespaces that 404 rather than degrade when mixed: `claude-code` wants
a bare family name (`sonnet`), OpenRouter wants a vendor slug
(`anthropic/claude-sonnet-4`), a local server has neither and is **asked** via
`/v1/models`.

`chat()` never raises on an API error — it returns a `ChatResult` carrying `.error`, so a
sweep scores a model as "failed to respond" rather than crashing.

## Disciplines that are enforced in code, not asserted

These are the repo's actual invariants. Breaking one is a correctness bug, not a style
preference — the reasoning lives in the docstrings, which are unusually load-bearing here.

- **Citations are validated, never trusted.** `validate_citations()` splits a model's
  claimed URLs against what the provider actually retrieved. An unretrieved URL is an
  *invented* citation and must not reach a ledger. Only strings starting `http` are
  judged — a search query in a sources list is a non-URL, not a fabrication, and crying
  wolf destroys the one check that must stay trustworthy.
- **A missing API key is FATAL, never a quiet no-op.** A scheduled loop that silently does
  nothing forever is an error masquerading as a low count. This bit this codebase once.
- **Pre-registration before grading; criteria before outcome.** `freeze_check` proves from
  git history that a claim's criteria were committed before its resolve date. It proves
  the *test* was fixed in advance — never that the verdict is right.
- **Ledgers are append-only.** A record belongs to the instance that made the predictions;
  imported claims are quarantined to `imported/` and never graded as the receiver's own.
- **`possible_states` / `UNLISTED`.** Predictions must name the states the entity could
  actually end up in, including the do-nothing one. An outcome nobody listed is the most
  informative result available and must never be forced into the nearest listed state.
- **Arena blindness is tested, not claimed.** The judge never sees a `MODEL.md`; nobody
  sees a sealed outcome before the ruling; every minute is signed. `arena_test.py`
  intercepts prompts and asserts what is *not* in them. Test artifacts are namespaced
  (`TAG = "selftest"`) because an unnamespaced run once destroyed a real one.
- **Kinds are load-bearing.** `suites/kinds/KINDS.md` defines eleven kinds by *what
  falsifies each*, which changes premise shape, watch frame, and the question the agentic
  pass asks. Two kinds ship with the falsifier marked as an open question rather than a
  fabricated answer — keep it that way.

## Platform and hygiene notes

- **`.env` is present and untracked.** Do not read it, print it, or commit it.
  `.env.example` documents the schema.
- **`*.sh` and Dockerfiles must stay LF** — pinned in `.gitattributes`. Git's autocrlf
  rewrote them to CRLF once, which breaks `bash` (`syntax error near unexpected token
  $'in\r'`) and breaks again inside the Linux containers where they actually run.
- **Windows paths into Git Bash** have bitten this repo three ways: backslashes read as
  escapes, drive letters unknown, `/f/...` failing from a spawned shell. `compat_check`
  runs `bash -n` from the script's own directory with a bare filename.
- **`localhost` inside a container** is the container. Wrappers rewrite it to the
  docker-host alias.
- Every suite reconfigures stdout/stderr to UTF-8 on import — keep that when adding one.
- Gitignored local data, not source: `inbox/ imports/ trajectory/ audits/ povs/`,
  `ui/inbox.jsonl`, and `suites/kinds/my_kinds.json` (read before the shipped packs and
  wins on a name collision, so an engine update never overwrites a user's discipline).
- Large data files at the root (`index.jsonl` ~1.2MB, `timeline.json`,
  `expert_timeline.json`) are generated stores — don't read them whole to answer a
  question.

## Suite families

~79 modules in `suites/`, all the same shape: argparse `main()`, `sys.path.insert` to the
repo root, `--repo` resolved against the fleet, append-only ledger writes. Grouped by job:

- **scaffold / publish** — `new_model`, `starter`, `make_card`, `make_use`, `make_tasks`,
  `publish_model`, `validate_card`, `import_model`, `legitimacy_audit`
- **the loop** — `model_watch`, `grading_loop`, `gather_evidence`, `grade_claims`,
  `trajectory`, `postmortem`, `freeze_check`, `calibrate`
- **arena** — `arena`, `arena_test`, `board`
- **modeling people** — `worldview`, `model_import`, `expert_timeline`, `merge_identity`;
  corpora built by `harness/ingest_youtube.py`, `ingest_substack.py`, `ingest_doc.py`
- **meta (level 1+)** — `classify`, `hindsight_audit`, `blindspot`, `attribute_outcomes`,
  `decision_trace`
- **map / memory / viz** — `reality_map`, `memory_index`, `mindmap`, `mesh_map`,
  `mesh_viz`, `sensing_map`, `model_graph`, `substrate_map`, `visualize`
- **safety** — `compat_check`, `review_untrusted`, `audit_sample`

## Vocabulary

**kind** — forecaster · classifier · tracer · finder · tracker · generator · attributor ·
adversary · mirror · timer. **level** — 0 models the world · 1 models models · 2 models
the modelling process. **aspects** and **e_span** (E0–E14 floors) are enumerated in
`docs/MODEL_SPEC_V1.md`; `docs/GLOSSARY.md` has the rest.
